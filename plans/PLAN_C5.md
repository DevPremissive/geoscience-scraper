# PLAN C5 — Text & Reports: Due-Diligence RAG, Barren Confirmation, Corpus-Scale Features

**Read `MASTER_PLAN.md` §2–§4 first.** The assessment-report corpus (150k+ reports
enumerable nationally: ON AFRI 100k+, BC ARIS 33.5k, SK SMAD ~14.9k, NL GeoFiles 5k+,
NS DCDH, NB PARIS, NTGS) is the richest exploration knowledge that exists for this
ground and currently sits at zero bytes on disk. Three uses, built in this order —
value-per-token descending, effort ascending:

1. **Target-time due diligence** (per-deal RAG — small, immediate, Phase 2)
2. **Barren confirmation** (Tier-2 negative upgrades + intercept positives — Phase 2)
3. **Corpus-scale harvest + NER features** (heavy, deferrable — Phase 4)

**Depends on:** C3.4 (`fetch_reports`), C0.1 (OAFD index repair for ON ID resolution),
local LLM stack (chat `:8082`, mxbai `:8083`, ChromaDB, rag-proxy `:9100`).
**Feeds:** C4 dossier sections 6–7, C2.4 Tier-2 negatives + `nonbarren_holes`, C6.4
historical-information value, C2.7 text features (Phase 4). Shares feedstock with `pmx`.
**Estimated effort:** 5.1 ≈ 4 days · 5.2 ≈ 4 days · 5.3 ≈ 4–5 days scraping for the
first two systems (per `SCRAPERS_BLOCKED.md`) + 1–2 weeks NER pipeline.
**New package:** `src/text/` — `ingest.py`, `dd_rag.py`, `extract_assays.py`, `ner.py`.

---

## 5.1 Target-time due-diligence RAG (~4 days)

Per-target pipeline: `fetch_reports(geometry)` (C3.4) → ingest → query → dossier
sections. Dozens of PDFs per deal, never a province.

**Ingestion (`ingest.py`):**
- Extend the existing `pdf_extract.py` (95 lines, written but never run at scale):
  text extraction with an **OCR fallback** (ocrmypdf/tesseract) triggered when
  extractable-text density falls below a threshold — a large fraction of pre-1990
  assessment reports are scans; without OCR the corpus's best negatives and intercepts
  are invisible.
- Chunking: page-anchored chunks (~1–2k chars, overlap) preserving `(report_id, page)` —
  the citation unit. Detect and specially tag table-dense pages (assay tables) for 5.2.
- Embedding: mxbai `:8083`; ChromaDB **collection per target**
  (`dd_<target_id>`), metadata per chunk: report_id, page, year, work_types, juris.
  Collection metadata records embedding model + dimension (verified at runtime).

**Query layer (`dd_rag.py`):** a fixed question set, run per target, each answer with
citations `(report_id, page)` — free-form chat exists but the dossier consumes the
standard set:
1. Chronological work history on/near the target (what was done, when, by whom).
2. Best historical results (assays, intercepts, anomalies) with verbatim figures.
3. What hypotheses were being tested, and did they change between report campaigns.
4. Apparent reason work stopped (stated plans never executed, funding language,
   "results did not warrant…").
5. Untested recommendations (recommended-but-never-drilled targets are gold for the
   sales narrative).
6. Any mention of the specific cells under consideration.

Answers are generated by the local chat model over retrieved chunks with a strict
"cite or say not-found" prompt contract; C4 renders them as dossier section 7. An
`answers.json` per target is stored with chunk provenance so regeneration is pinned.

**Acceptance:** for one Ontario target with ≥10 AFRI reports: all six answers cited;
a human spot-checks 10 citations against the PDFs and finds no fabricated figures;
an OCR'd scanned report contributes at least one cited answer.

## 5.2 Barren confirmation & intercept extraction (~4 days)

Purpose: upgrade C2.4 Tier-1 provisional negatives to **Tier-2 confirmed**, and extract
the positive corollary — intercepts on dropped ground.

**Pipeline (`extract_assays.py`):**
1. Input: (hole_id, report_id) pairs — from OAFD/ARIS index metadata linking reports to
   drill programs, or from 5.1 retrieval when the link is implicit.
2. Table extraction on tagged table-dense pages: pdfplumber first, camelot fallback;
   OCR'd pages go through the same extractors on the OCR text layer.
3. LLM extraction pass (local `:8082`, JSON-schema-constrained output) over conclusions
   text + extracted tables:
   `{hole_id_in_report, depth_from, depth_to, commodities_assayed[],
     best_result_per_commodity, verdict ∈ {barren, mineralized, ambiguous},
     verdict_quote, page}`.
4. Write-back:
   - `verdict == barren` → C2.4 negatives upgraded to Tier 2 with
     `report_id + assay_summary`, `review_status = auto`.
   - `verdict == mineralized` → row in `nonbarren_holes.parquet` with the intercept and
     citation — a first-class C4 dossier item and C6 valuation input.
   - `ambiguous` → human review queue.
5. **QA gate (binding):** 10% random sample of every batch human-reviewed before any
   Tier-2 label enters model training (C2.4 consumption rule); measured precision goes
   on the batch record. Extraction that can't hit ≥95% verdict precision on the sample
   stays out of training (dossier veto flags may still show it, marked `auto`).

**Acceptance:** ≥50 holes processed across ≥10 reports; sample precision measured and
recorded; at least one Tier-1→Tier-2 upgrade and one intercept extraction render
correctly in a dossier.

## 5.3 Corpus-scale harvest + NER features (Phase 4)

**Harvest order and rationale:** BC ARIS first (33.5k — richest per-report content),
then ON AFRI (100k+ — best-documented stub, biggest volume). Remaining systems
(SK SMAD, NL GeoFiles, NS DCDH/NovaScan, NB PARIS, NTGS) follow the per-system
remediation strategies and effort estimates in `SCRAPERS_BLOCKED.md`, executed
on-demand when deal flow touches the jurisdiction (per C3.4 policy) or when Phase-4
capacity allows. All scraping reuses the Camoufox session manager; strict politeness
(these are public-good archives). Storage: `pdfs/<JURIS>/<CODE>/<id>.pdf` + sidecars;
volume planning per the storage budget already provisioned (ON alone 30–80 GB).

**Corpus ingestion:** the 5.1 pipeline at scale — batch OCR triage, one Chroma
collection per jurisdiction-system (distinct from per-target DD collections), embedding
throughput measured before committing to national scale.

**NER → cell features (`ner.py`):**
- Entities: rock units, minerals, alteration terms, structural terms, work types,
  drill intercepts, commodities, geographic/claim references.
- v1: prompt-based extraction with the local model against a fixed entity schema
  (no fine-tuning until volume justifies); evaluate on a 200-report hand-labeled sample.
- Geolocation: reports carry township/claim/NTS references — resolve to geometries via
  the tenure and index layers; unresolvable reports get jurisdiction-level tags only
  (never guessed coordinates).
- Feature emission: per r7 cell — entity frequency vectors, work-intensity counts
  (metres drilled, trenches, surveys flown), and "recommended-but-untested" flags →
  feature store for C2.7. A knowledge-graph layer is explicitly optional and deferred
  until the flat features prove insufficient.
- Downstream sharing: `pmx` consumes the same PDFs for NI 43-101/DCF work — coordinate
  storage layout, don't duplicate corpora.

**Acceptance:** ARIS harvest complete with <2% fetch failures; NER sample F1 reported;
one C2 model retrained with text-corpus features shows the feature family registering
in SHAP (whether or not it dominates — the honest result is the requirement).
